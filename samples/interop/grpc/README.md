# gRPC

Triple speaks the gRPC protocol over HTTP/2, so gRPC programs in any language
call Dubbo services, and Dubbo calls gRPC services, with nothing in between.
This sample does both in Python, with `grpcio` on the gRPC side.

## What you will learn

- how a plain gRPC client calls a Dubbo provider;
- how a Dubbo consumer calls a plain gRPC server;
- how to turn on the gRPC health and reflection services, for tools such as
  `grpcurl` and for health probes.

## Before you start

```console
$ pip install grpcio
```

## The files

| File | Role |
|---|---|
| `greeter.proto` | The contract both sides generate code from |
| `greeter_pb2.py`, `greeter_pb2.pyi` | The messages, generated by protoc |
| `greeter_pb2_grpc.py` | The gRPC stub and servicer, generated by `--grpc_python_out` |
| `greeter_dubbo.py` | The Dubbo contracts, generated by `--python-dubbo_out` |
| `dubbo_server.py`, `grpc_client.py` | A Dubbo provider and a gRPC client of it |
| `grpc_server.py`, `dubbo_client.py` | A gRPC server and a Dubbo consumer of it |

The generated files are included. To generate them again, with the `protoc`
extra installed:

```console
$ python -m grpc_tools.protoc -I. --python_out=. --pyi_out=. --grpc_python_out=. --python-dubbo_out=. greeter.proto
```

## Run it

### A gRPC client calls Dubbo

From this directory:

```console
$ python dubbo_server.py
Serving on port 50051; press Ctrl+C to stop
```

```console
$ python grpc_client.py
Hello, gRPC, from Dubbo!
```

### Dubbo calls a gRPC server

```console
$ python grpc_server.py
Serving on port 50052; press Ctrl+C to stop
```

```console
$ python dubbo_client.py
Hello, Dubbo, from gRPC!
```

### Health and reflection

With `dubbo_server.py` running, [grpcurl](https://github.com/fullstorydev/grpcurl)
lists the services through reflection, calls the Greeter without any proto
file, and checks health:

```console
$ grpcurl -plaintext 127.0.0.1:50051 list
$ grpcurl -plaintext -d '{"name": "grpcurl"}' 127.0.0.1:50051 org.apache.dubbo.samples.Greeter/SayHello
$ grpcurl -plaintext 127.0.0.1:50051 grpc.health.v1.Health/Check
```

## How it works

Both sides generate code from the same `greeter.proto`. The service keeps the
full name of the proto, `org.apache.dubbo.samples.Greeter`, and its methods
their proto names, `SayHello`, on the wire, whatever their Python names.

The Dubbo provider serves Triple, which a gRPC client reads as gRPC. The Dubbo
consumer refers to the gRPC server with a `tri://` URL, as to any Triple
provider.

`health_enabled` and `reflection_enabled` under `triple` add the standard
`grpc.health.v1.Health` and `grpc.reflection.v1.ServerReflection` services.
Health reports each exported service as serving until the application
stops. Neither is registered with a registry.
