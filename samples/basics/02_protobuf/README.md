# Protobuf and Triple

Define the contract in a `.proto` file, generate Python code from it, and
serve it over Triple, the protocol of Dubbo that gRPC also speaks.

## What you will learn

- how to generate a Dubbo contract from a `.proto` file;
- how a provider implements the generated servicer;
- how a consumer calls the generated protocol over Triple.

## Why Protobuf

A `.proto` file is a contract that every language reads: Dubbo Java, Dubbo Go
and gRPC programs generate code from the same file. Use it when services in
several languages share a contract, or when gRPC clients call your service.
The [hello world](../01_hello_world) sample shows the other way, with
contracts written in Python.

## The files

| File | Role |
|---|---|
| `greeter.proto` | The contract |
| `greeter_pb2.py`, `greeter_pb2.pyi` | The messages, generated by protoc |
| `greeter_dubbo.py` | The Dubbo contracts, generated by `protoc-gen-python-dubbo` |
| `server.py` | The provider: implements `GreeterServicer` on port 50051 |
| `client.py` | The consumer: calls `Greeter` at `tri://127.0.0.1:50051` |

## Generate the code

The generated files are included, so you can skip this step. To generate
them again after changing `greeter.proto`, install the `protoc` extra and run
protoc from this directory, with the virtual environment activated so that
protoc finds the plugin:

```console
$ pip install "apache-dubbo[protoc]"
$ python -m grpc_tools.protoc -I. --python_out=. --pyi_out=. --python-dubbo_out=. greeter.proto
```

`--python_out` and `--pyi_out` write the message classes, as for any Python
use of Protobuf. `--python-dubbo_out` runs `protoc-gen-python-dubbo`, which
writes `greeter_dubbo.py` with two classes for each service:

- `Greeter`, a `typing.Protocol` that consumers refer to;
- `GreeterServicer`, an abstract class that providers subclass.

## Run it

From this directory, start the server:

```console
$ python server.py
Serving on port 50051; press Ctrl+C to stop
```

In another terminal, run the client:

```console
$ python client.py
Hello, Dubbo!
```

## How it works

The server configures no protocol, so the application serves Triple on port
50051. Each `rpc` of the proto file becomes a method with a Python name:
`SayHello` becomes `say_hello`, and the service keeps its full name,
`org.apache.dubbo.samples.Greeter`, so that other languages find it.

The client refers to `Greeter` with a `tri://` URL. Messages travel in the
Protobuf format, framed as gRPC frames them over HTTP/2.
